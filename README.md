# History Teaching Skills

> 面向高中历史教师的可追溯 AI 备课工作流：从资料筛选、教学设计到原生 PowerPoint 课件。

![Version](https://img.shields.io/badge/version-H4-1E869F)
![License](https://img.shields.io/badge/license-MIT-C69A4B)
![Workflow](https://img.shields.io/badge/workflow-TRAE-0A151C)

本项目将高中历史备课拆分为三个相互衔接、又可独立使用的 Skill：

1. `curate-history-sources`：筛选资料、核验来源、对照课程标准；
2. `design-history-lesson`：形成教学主线、问题链和完整教学设计；
3. `build-history-classroom-pptx`：生成原生可编辑的课堂 PPTX 与教师备注。

它不是“输入课题后自动生成一套课件”的黑箱工具，而是一套强调证据、教师确认和课堂可用性的工作流规则。

## 项目要解决什么问题

AI 备课常见的问题并不是“生成得不够快”，而是：

- 引文、数据和历史观点没有可靠出处；
- 文学化教学主线挤占了基础知识；
- 教学设计与课件之间缺少明确接口；
- 图片、地图、文物等视觉材料使用过于保守；
- 课件更像商务汇报，而不像真实课堂；
- 标题层级、动画、学生笔记和文字容量缺乏验收。

本项目尝试把一线教学中的判断标准写成 AI 能执行、教师能检查的约束。

## 核心原则

- **证据可追溯**：史料、数据、观点和课标表述必须标明来源与核验状态，禁止凭记忆补写。
- **教师保留决定权**：教学主线、联网补证、逐页素材和关键取舍均设置教师确认关口。
- **知识不能被主线替代**：课件必须落实知识覆盖矩阵，服务讲授、理解与学生笔记。
- **视觉材料服务认识**：主动规划文物、地图、遗址、图表、漫画等材料，但不擅自下载或插入外部媒体。
- **课件面向真实课堂**：反对卡片墙、仪表盘、KPI 和通用商务模板，允许教学必要的高密度页面。
- **成品必须可验收**：标题层级、文字溢出、动画、页码残留、制作残留和构图重复均进入检查流程。

## 工作流总览

资料筛选启动时，先在教师指定的资料文件夹内建立 `yyyyMMdd-HHmmss_Trae_课标题` 任务目录。三个Skill产生的摘要、教学设计、课件、中间文件和检查报告全部保存在该目录中；原始备课资料保持只读。

```text
教师备课文件夹
      │
      ▼
curate-history-sources
      │  资料筛选、课标对照、定向补证、主线建议
      ▼
资料核心摘要.md
      │
      ▼
design-history-lesson
      │  教学环节、问题链、知识矩阵、逐页课件接口
      ├──────────────┬────────────────┐
      ▼              ▼                ▼
教学设计.md    课件制作清单.md    课件素材建议表.md
      └──────────────┴────────────────┘
                      │
                教师逐页确认素材
                      │
                      ▼
build-history-classroom-pptx
                      │  原生PPTX、动画、备注、结构与视觉验收
                      ▼
              课堂课件.pptx
              教师备注.md
```

| 阶段 | 主要输入 | 主要输出 | 必须由教师确认 |
|---|---|---|---|
| 资料筛选 | 已整理的备课文件夹、课程标准 | `资料核心摘要.md` | 联网补证范围、最终教学主线 |
| 教学设计 | 已确认的资料摘要与主线 | 教学设计、课件清单、素材建议表 | 目标、环节、问题链与课件接口 |
| 课件制作 | 上游全部文档、逐页素材选择 | `课堂课件.pptx`、`教师备注.md` | 每页是否使用素材及占位方式 |

## 三个 Skill

### 1. `curate-history-sources`

遍历教师已经筛选过的备课文件夹，完成资料审计、课程标准对照、知识缺口分析和必要的定向联网补证。

主要能力：

- 并列呈现《普通高中历史课程标准》2025 年修订文本与 2020 年修订文本；
- 说明两版课标的具体表述变化，并生成课件可直接使用的课标接口；
- 按来源可靠性分级处理本地资料和网络资料；
- 区分事实、史料原文、学者观点、教学案例和待核验信息；
- 默认提出三条有史学依据的教学主线，禁止自创专业术语；
- 为 40—45 分钟课时规划 8—12 项 A/B 级视觉证据意图；
- 对参考 PPT 采用低分辨率联系表进行轻量审计，避免无差别提取全部媒体。

该阶段不撰写完整教学设计，不制作课件，也不下载图片或视频。

### 2. `design-history-lesson`

把已经核验的资料转化为可实施的课堂方案，并建立教学设计与课件制作之间的明确接口。

主要能力：

- 以“教学环节”而不是机械节拍组织教学过程；
- 建立目标、评价、知识覆盖和课堂活动之间的对应关系；
- 导入兼顾趣味性与严谨性，优先从著名文物切入并引出核心问题；
- 主线中的史学论断和专业术语必须有理论支撑，文学化标题与史学判断严格区分；
- 综合规划文物、图片、地图、表格、示意图、漫画等不同材料；
- 为每个拟定页面输出独立的 L1/L2/L3 标题路径；
- 明确视觉中心、构图家族、互动表格动画和流程图关系结构；
- 同时输出课件制作清单与课件素材建议表，供下一阶段直接读取。

### 3. `build-history-classroom-pptx`

依据已确认的教学设计和逐页接口，生成原生可编辑的 PowerPoint 课件，而不是把 HTML 或网页截图转换成 PPT。

主要能力：

- 固定 33.867 cm × 19.05 cm、16:9 画布；
- 默认使用统一稳定视觉语言，主识别色为 `#1E869F`；
- 所有常规内容页使用统一顶栏、底栏和独立 L1/L2/L3 标题对象；
- 正文不小于 24 pt，标题不小于 28 pt，结论条不小于 32 pt；
- 每个主体环节完成“材料/知识支架—任务—处理—答案—结论”课堂认知链；
- 区分导入锚点、教学主线与核心问题，逐环节检查主线是否真正增加答案；
- 互动表格保留真正空白单元格，答案在同一页通过独立文本框动画揭示；
- 双版本课标原文保存在末尾隐藏附录，不打断学生主放映顺序；
- 允许保留教师后补的图片、地图、漫画和视频占位符，但占位符不得替代知识、任务、答案和结论；
- 至少使用四类课堂构图，避免连续同构图和矩形卡片墙；
- 强制检查课堂可用性、文字溢出、动画时间轴、页码残留、制作残留和标题层级。
- 底栏不显示左下角“笔记”提示，也不显示右下角页码或当前页/总页数。

最终只交付课件和备注：

- `课堂课件.pptx`
- `教师备注.md`

构建脚本、素材确认表、渲染图和检查记录只保留在任务工作区。

## 快速开始

### 公开版与个人私有模板

本仓库发布的是**公开基础版**：包含完整工作流、文字化云校视觉规范和私有模板接入口，但不包含学校所有的云校模板文件。

个人使用时，可在课件 Skill 内建立以下本地目录：

```text
build-history-classroom-pptx/
└── private-assets/
    └── templates/
        ├── cloud-school-dark.pptx
        └── cloud-school-light.pptx
```

`private-assets/` 已被 `.gitignore` 排除。请勿强制添加、提交或发布其中的文件。

课件 Skill 按以下顺序选择视觉来源：

1. 用户在当前任务中明确指定的模板；
2. 本机 `private-assets/templates/` 中的对应云校模板；
3. 仓库内的文字化深色或浅色视觉规范。

因此，公开用户没有学校模板也能运行；教师本人安装私有模板后，则会优先依据真实模板审阅和手工重建设计语言。模板只作为本地输入，不会进入最终课件交付或开源仓库。

### 运行环境

- [TRAE](https://www.trae.ai/) 或其他支持 Skill 机制的 AI 编程环境；
- Node.js 与 [PptxGenJS](https://github.com/PptxGenJS/PptxGenJS)，用于生成原生 PPTX；
- Windows 桌面版 PowerPoint，用于写入和检查原生动画、重新打开文件及检测文字溢出；
- 《普通高中历史课程标准 日常修订版（2017 年版 2025 年修订）》PDF。

如果运行环境无法完成原生 PPTX、动画、逐页渲染或溢出检查，课件 Skill 应停止，而不是静默改成 HTML、截图或图片化页面。

### 安装

克隆或下载本仓库：

```bash
git clone https://github.com/zyl1441701186-byte/history-teaching-skills.git
```

将 `skills/` 下的三个目录复制到 TRAE Skills 目录。Windows 常见位置为：

```text
C:\Users\<用户名>\.trae-cn\skills\
```

安装后的结构应为：

```text
<TRAE_SKILLS_DIR>/
├── curate-history-sources/
│   ├── SKILL.md
│   └── references/
├── design-history-lesson/
│   ├── SKILL.md
│   └── references/
└── build-history-classroom-pptx/
    ├── SKILL.md
    ├── agents/
    ├── references/
    └── scripts/
```

课程标准 PDF 因体积原因未包含在仓库中。请将文件命名为：

```text
curriculum-standard-2017-2025.pdf
```

并放入：

```text
curate-history-sources/references/
```

## 使用示例

### 完整工作流

第一步，筛选资料：

```text
请使用 curate-history-sources，遍历“D:\我的备课资料\第7课”，
完成双版本课标对照、资料核验、知识缺口分析和教学主线建议。
```

确认资料摘要和教学主线后：

```text
请使用 design-history-lesson，根据已经确认的《资料核心摘要.md》撰写教学设计，
同时生成课件制作清单和课件素材建议表。
```

完成逐页素材选择后：

```text
请使用 build-history-classroom-pptx，根据已经确认的教学设计、课件制作清单、
课件素材建议表和资料摘要生成原生课堂PPTX与教师备注。
```

### 单独使用

三个 Skill 可以单独调用，但必须满足各自的启动条件。特别是课件制作 Skill 不应绕过资料摘要、知识覆盖矩阵、逐页标题接口和素材确认表自行补写内容。

## 人机协作边界

### AI 可以做

- 遍历和归纳用户授权范围内的资料；
- 按规则定向联网补证并记录来源；
- 提出有依据的教学主线、问题链和材料组合；
- 生成原生可编辑的教学文档与 PPTX；
- 执行结构、动画、容量和视觉检查。

### AI 不应擅自做

- 凭记忆补写史料原文、数据、课标或学术观点；
- 无边界搜索网络并把搜索摘要当作可靠证据；
- 自动下载、筛选或插入外部图片和视频；
- 使用自创史学概念包装教学主线；
- 用文学化表达替代基础知识；
- 为了塞入内容而缩小字号、自动缩字或删除知识；
- 把课件做成商务汇报、HTML 页面或整页截图。

## 适用范围

适合：

- 使用统编高中历史教材的一线教师；
- 希望建立统一备课规范的教研组；
- 需要理解完整备课链路的师范生和新教师；
- 关注 AI 教育应用可控性、可追溯性和可维护性的开发者。

暂不适合：

- 希望完全无人干预地批量生成课件；
- 没有课程标准和基本备课资料，只希望 AI 自行补全全部内容；
- 无法运行 Windows PowerPoint，却要求完整原生动画与最终视觉验收；
- 希望自动抓取和批量插入网络图片、视频或受版权保护素材。

## 版本规则

当前版本：**H4**

- `V1`：仓库最初公开的 4.0 工作流；
- `H2`：基于真实课件问题完成的第二个公开迭代版本；
- `H3`：区分公开基础版与本地私有模板覆盖层；
- `H4`：以真实课堂可用性取代单纯格式合规，允许教师后补媒体，但严查信息密度、课堂认知链与空心占位页；
- 后续版本依次使用 `H5`、`H6`……，其中 `H` 取自 History。

具体变化见 [CHANGELOG.md](CHANGELOG.md)。
